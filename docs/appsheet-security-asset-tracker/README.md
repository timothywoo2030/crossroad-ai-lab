# 보안 하드웨어 자산 반출입 추적 앱 — AppSheet 설계 명세

사내 기밀 보안 음향 디바이스 등 고유 하드웨어 자산의 실시간 반출입을 기록하는 반응형 모바일/웹 앱의 AppSheet 구현 명세입니다. AppSheet은 노코드 플랫폼이므로 이 문서는 "소스코드"가 아니라 **Google AppSheet 에디터에 그대로 옮겨 넣을 테이블·수식·Bot 설정**입니다.

> **전제 조건 [확인 필요]**: 아래 OCR/AI 추출 기능(AI Task · Extract)은 2025-07-16 기준 Google Workspace 발표로 **AppSheet Enterprise Plus 플랜에서 일반 공급(GA)** 되었습니다. 현재 조직의 플랜이 Enterprise Plus인지 먼저 확인하십시오. 하위 플랜이면 아래 "OCR 대체 경로"로 전환해야 합니다. [기준일: 2025-07-16]

---

## 1. 테이블 스키마

### 1-1. `보안_하드웨어_자산_마스터`

| 컬럼 | 타입 | 설정 |
|---|---|---|
| 자산_코드 | Text | Key, `NOTBLANK()`, 바코드/QR 스캔 연동(아래 1-4 참고) |
| 기기_모델명 | Text | — |
| 인가_보안등급 | Enum | Base Type: Text, Values: `일반`, `대외비`, `극비` (순서 고정 — 2-1 참고) |
| 현재_대여_가능여부 | Yes/No | Initial value `TRUE` |
| 보관_물리_위치 | Text | — |

**자산_코드** 컬럼의 `Scan with barcode` 옵션을 켜면 모바일 카메라로 QR/바코드 자산 태그를 직접 읽어 Key 값을 채울 수 있습니다. 이것은 1-4의 OCR 워크플로우와는 별도 경로(QR 라벨이 있는 자산용)이며, 시리얼 넘버만 인쇄된 레거시 장비는 OCR 경로를 씁니다.

### 1-2. `임직원_프로필`

| 컬럼 | 타입 | 설정 |
|---|---|---|
| 사원번호 | Text | Key |
| 이름 | Text | — |
| 소속_부서 | Text | — |
| 인가_보안등급 | Enum | `보안_하드웨어_자산_마스터.인가_보안등급`과 **동일한 Enum 값 목록**을 공유해야 함(아래 2-1) |

보안 검토 포인트: 이 테이블은 `USEREMAIL()` 기반 Security Filter로 **본인 레코드만 조회**하도록 제한하고(동료 보안등급 열람 차단), 관리자 역할만 전체 조회·수정 권한을 갖도록 합니다(아래 4장).

### 1-3. `반출입_실시간_트랜잭션_로그`

| 컬럼 | 타입 | 설정 |
|---|---|---|
| 로그_ID | Text | Key, App formula `UNIQUEID()` |
| 자산_코드_Ref | Ref → 보안_하드웨어_자산_마스터 | `Valid_If`: 아래 2-2 |
| 사원번호_Ref | Ref → 임직원_프로필 | Initial value `USERSETTINGS([현재_사용자_사원번호])` 또는 로그인 이메일 매칭 |
| 반출_일시 | DateTime | Initial value `NOW()`, Editable `FALSE`(위변조 방지) |
| 반납_예정일 | Date | `Valid_If`: `[반납_예정일] > TODAY()` |
| 실제_반납_일시 | DateTime | Nullable, Show_If `NOT(ISBLANK([실제_반납_일시]))`일 때만 "반납 처리" 액션으로 서버 타임스탬프 기록 |
| 모바일_서명란 | Signature | 반출 Form 제출 전 필수(`Required_If`) |
| 자산_명판_스냅사진 | Image | 모바일 카메라 촬영, OCR 소스(아래 3장) |

추가 권장 컬럼(스키마 확장, 선택):
- `권한_미달_경고` (Virtual column, Yes/No) — 2-2의 판정 결과를 로그에도 영구 기록해 사후 감사 추적.
- `승인_상태` (Enum: 대기/승인/거부) — 권한 미달 건을 **차단이 아니라 승인 대기**로 운영하고 싶을 때.

### 1-4. 스캔/인식 입력 경로 요약

| 자산 라벨 형태 | 입력 방식 | 담당 컬럼 |
|---|---|---|
| QR/바코드 라벨 부착 자산 | 네이티브 바코드 스캐너 | `자산_코드_Ref` 직접 매핑 |
| 시리얼 번호만 인쇄된 레거시 자산 | 카메라 촬영 + AI OCR | `자산_명판_스냅사진` → Bot이 `자산_코드_Ref` 역매핑(3장) |

## 2. 보안등급 비교 로직

### 2-1. Enum 순서를 숫자로 환산

AppSheet의 Enum은 선택 목록일 뿐 "일반 < 대외비 < 극비" 같은 서열을 자체적으로 비교하지 못합니다. 두 테이블 모두에 아래 **App Formula 방식 Virtual Column**을 추가합니다.

`임직원_프로필`에 Virtual Column `사원등급_순위` (Type: Number):
```
IFS(
  [인가_보안등급] = "일반", 1,
  [인가_보안등급] = "대외비", 2,
  [인가_보안등급] = "극비", 3,
  TRUE, 0
)
```

`보안_하드웨어_자산_마스터`에 Virtual Column `자산등급_순위` (Type: Number): 위와 동일한 수식.

> 등급 항목을 추후 추가·변경할 경우 **이 두 IFS 수식을 반드시 동시에 수정**해야 합니다. 두 테이블의 등급 목록이 어긋나면 비교 로직 전체가 무력화됩니다.

### 2-2. `반출입_실시간_트랜잭션_로그`의 권한 판정 Virtual Column

`권한_미달_여부` (Type: Yes/No):
```
AND(
  NOT(ISBLANK([자산_코드_Ref])),
  NOT(ISBLANK([사원번호_Ref])),
  [사원번호_Ref].[사원등급_순위] < [자산_코드_Ref].[자산등급_순위]
)
```

### 2-3. 권장안 — 경고 표시 + 반출 자체 차단 (추천)

단순 "붉은 경고 표시"만으로는 권한 미달자가 서명 후 그대로 반출을 완료할 수 있습니다. 기밀 보안 장비라는 자산 특성상, **경고 표시(소프트)와 제출 차단(하드)을 함께** 적용하는 것을 추천합니다 — 사후 적발보다 사전 차단이 보안 사고 비용을 훨씬 낮추기 때문입니다.

- **소프트 경고(실시간 UX)**: `자산_코드_Ref`를 선택하는 순간 폼 화면에 즉시 표시(아래 3-3 Format Rule).
- **하드 차단(제출 저지)**: `자산_코드_Ref` 컬럼 `Valid_If`에 아래 수식 추가.
```
OR(
  ISBLANK([_THISROW].[자산_코드_Ref]),
  [_THISROW].[사원번호_Ref].[사원등급_순위] >= [_THISROW].[자산_코드_Ref].[자산등급_순위]
)
```
`Invalid_If` 안내 문구: `"선택하신 자산({기기_모델명})의 인가등급이 귀하의 보안등급보다 높습니다. 부서장 승인 후 별도 승인 절차를 이용하세요."`

운영상 긴급 예외(부서장 동행 반출 등)가 필요하면, 하드 차단 대신 1-3의 `승인_상태` 컬럼을 두고 권한 미달 건은 "대기" 상태로 저장되어 **관리자 승인 전까지 실제 반출 액션(아래 3-4)이 비활성화**되는 절충안을 쓸 수 있습니다. 조직의 승인 체계(현장 즉시 예외 허용 여부)에 따라 결정하십시오.

## 3. OCR 기반 자산 코드 자동 매핑 워크플로우

### 3-1. 전체 흐름

```
[모바일 카메라로 시리얼 라벨 촬영]
        ↓ 자산_명판_스냅사진 컬럼에 저장 (Add/Edit 이벤트)
[Bot: OCR_자산코드_자동매핑] 트리거
        ↓ AI Task(Extract, Gemini) — 이미지에서 시리얼 번호 텍스트 추출
[추출된 문자열 정규화] (공백 제거, 대문자 변환)
        ↓
[보안_하드웨어_자산_마스터 테이블에서 자산_코드 매칭]
   ├─ 정확히 일치 → 자산_코드_Ref 자동 채움, 사용자에게 확인 토스트
   ├─ 유사하지만 불일치(오타 의심) → 후보 자산코드 Top-3 제시, 사용자 확인 요구
   └─ 매칭 실패 → "수동 입력 필요" 알림 + 관리자에게 예외 통지
```

### 3-2. Bot 설정 (AppSheet 에디터 기준)

- **Bot 이름**: `OCR_자산코드_자동매핑`
- **Event**: `반출입_실시간_트랜잭션_로그` 테이블, `Adds and Updates`, Condition:
  ```
  AND(
    NOT(ISBLANK([자산_명판_스냅사진])),
    ISBLANK([자산_코드_Ref])
  )
  ```
- **Process 단계 ①: AI Task(Extract)**
  - Input: `[자산_명판_스냅사진]` (Image 컬럼)
  - Task 유형: *Extract information from an image* (Gemini 기반, Enterprise Plus 전용)
  - 추출 스키마 예시(JSON 출력 형식 지정):
    ```json
    { "serial_number": "string — 라벨에 인쇄된 시리얼/자산 번호. 숫자·영문·하이픈만 포함, 그 외 텍스트는 무시" }
    ```
- **Process 단계 ②: 데이터 정규화 (Expression)**
  ```
  UPPER(SUBSTITUTE(TRIM([추출결과].[serial_number]), " ", ""))
  ```
- **Process 단계 ③: 매칭 (Expression, Change Record Values)**
  - 정확 일치 시도:
    ```
    LOOKUP([정규화된_시리얼], "보안_하드웨어_자산_마스터", "자산_코드", "자산_코드")
    ```
  - 일치하면 `자산_코드_Ref`에 즉시 Set Column Values.
  - 불일치 시 **오타 보정**: 전체 자산 코드 목록 중 편집거리 기반 최근접 값을 고르는 전용 로직이 AppSheet 표준 수식만으로는 제한적이므로, 아래 두 방법 중 선택합니다.
    1. **[권장]** Process 단계 ①의 AI Task 지시문에 "다음 유효 자산코드 목록과 비교하여 가장 유사한 코드와 신뢰도(0~1)를 함께 반환하라"는 문장을 넣고, `보안_하드웨어_자산_마스터`의 `자산_코드` 목록을 컨텍스트로 함께 전달 — Gemini가 OCR 오인식(0↔O, 1↔I 등)까지 보정한 후보를 직접 제시.
    2. 대안으로 별도 Apps Script/Cloud Function을 Webhook Task로 호출해 Levenshtein 거리 계산.
  - 신뢰도 0.85 미만이거나 후보가 여러 개면 `매칭_상태` 플래그를 "확인필요"로 설정.
- **Process 단계 ④: 사용자 알림**
  - 매칭 성공: 앱 내 Toast — `"자산코드 {코드}로 자동 인식되었습니다. 확인 후 제출하세요."`
  - 매칭 실패/저신뢰: Push 알림(해당 사용자) + 자산관리자 그룹에 이메일 — "자동 인식 실패, 수동 확인 필요: 로그_ID {로그_ID}".

### 3-3. 스마트 UX 뷰 — 실시간 경고 배너 (Format Rule)

반출 Form View(`반출입_실시간_트랜잭션_로그_Form`)에 Format Rule 추가:

- **적용 대상 컬럼**: `자산_코드_Ref`
- **조건**: `[권한_미달_여부]` (2-2에서 정의)
- **서식**: 배경색 `#D32F2F`(적색), 텍스트 흰색, 아이콘 ⚠️
- **동반 안내 라벨**(Display name 또는 별도 Label 위젯): `CONCATENATE("⚠ 권한 미달: 요청자 등급(", [사원번호_Ref].[인가_보안등급], ") < 자산 등급(", [자산_코드_Ref].[인가_보안등급], ")")`

Detail View와 목록(Table/Deck) View에도 동일한 `권한_미달_여부` 기준 Format Rule을 적용해, 이미 생성된 로그 레코드를 열람할 때도 과거 위반 건이 한눈에 드러나도록 합니다.

### 3-4. 반납 처리 액션

- **Action 이름**: `반납_처리`
- Behavior: `Data: set the values of some columns in this row`
- Set: `실제_반납_일시 = NOW()`
- Only_if_condition: `AND(ISBLANK([실제_반납_일시]), [승인_상태] <> "대기")` (승인 대기 건은 반출 자체가 안 되었으므로 반납도 불가)
- 반납 완료 시 연결된 `보안_하드웨어_자산_마스터.현재_대여_가능여부`를 `TRUE`로 되돌리는 별도 Bot(`자산_반납_상태갱신`)을 둡니다.

## 4. 접근 권한 및 감사 요건

1. **Security Filter**: `임직원_프로필`은 `[사원번호] = CONTEXT("User")` 조건으로 본인 레코드만 노출(관리자 역할 제외). 타인의 보안등급이 노출되면 그 자체로 정보 유출입니다.
2. **로그 불변성**: `반출_일시`, `로그_ID`는 Editable `FALSE`로 잠가 사후 조작을 막습니다. 수정이 필요하면 새 보정 로그를 추가하는 방식(append-only)을 원칙으로 하십시오.
3. **서명·사진 원본 보존**: `모바일_서명란`, `자산_명판_스냅사진`은 AppSheet 기본 설정상 클라우드 스토리지(Google Drive 등) 연결 폴더에 저장됩니다. 보안 등급이 "극비"인 자산 사진은 전용 비공개 폴더로 분리 저장하고 접근 권한을 자산관리자로 제한하는 것을 권장합니다.
4. **AI Task 데이터 처리 범위 [확인 필요]**: Gemini 기반 Extract 작업에 전달되는 이미지가 조직의 데이터 거주/보존 정책(특히 "극비" 등급 자산 사진)에 부합하는지는 Google Workspace 관리자와 사전 확인이 필요합니다. 국가·업종별 보안 규정상 민감 이미지의 외부 AI 처리가 금지된 경우, 3-2의 AI Task 경로 대신 자산관리자 수동 입력 또는 온프레미스 OCR 엔진 연동으로 전환하십시오.

## 5. 구현 순서 제안

1. 3개 테이블 스프레드시트/DB 생성 → AppSheet 앱 생성 및 테이블 연결
2. Enum 값("일반/대외비/극비") 및 2-1의 순위 Virtual Column 설정 — **가장 먼저 처리**(이후 모든 로직이 여기에 의존)
3. 2-2, 2-3의 권한 판정 수식 및 Valid_If 적용 → 테스트 계정 2개(등급 불일치 조합)로 차단/경고 동작 검증
4. Enterprise Plus 플랜 여부 확인 → AI Task(Extract) Bot 구성, 실제 자산 라벨 사진 10장 이상으로 인식률 테스트
5. Format Rule·알림·반납 액션 구성
6. 보안 검토(4장) 및 접근권한 최종 점검 후 배포
